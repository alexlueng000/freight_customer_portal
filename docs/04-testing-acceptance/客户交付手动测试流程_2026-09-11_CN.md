> 编制日期：2026-09-10；计划执行日期：2026-09-11。

> 对照基线：[客户交付优化范围与验收计划](../05-project-management/客户交付优化范围与验收计划_2026-09-10_CN.md)。
> 本文是待执行清单，不是测试通过报告。所有结果由实际测试人填写。

## 1. 怎么使用这份文档

按第 2～6 节顺序测试，先用同一票业务走通主链，再检查异常与权限。最后执行第 7 节交付检查并填写结论。

- 通过：操作与预期全部一致，勾选对应编号。
- 失败：实际行为不符合预期，记录编号、业务单号和截图。
- 阻塞：账号、数据或服务缺失，无法测试；不能记为通过。
- 不适用：写明原因。安全和主链关键项目不能为了交付而改为不适用。

不需要测试完整报关、拖车调度、派送还箱、账单结算或船司接口，这些不属于本次交付。不要在主链测试单上操作拒绝或取消，异常测试另建记录。

## 2. 开始前准备

### P01：环境与服务

- [ ] 后台和客户门户可以打开。当前本地入口为 `http://localhost:3000/admin/login`、`http://localhost:3000/t/demo/login`；客户环境使用实际交付地址与门户标识。
- [ ] API、数据库、Redis、后台 worker 和 S3/MinIO 对象存储正常。
- [ ] 文件存储可上传和下载；报价 PDF 生成所需 worker 正常。
- [ ] 若交付包含邮件通知，配置了可实际接收邮件的测试邮箱，不能用“模拟发送成功”代替收到邮件。

**已知环境事项：2026-09-10 的本机主链测试在登记 SO 时返回过 `503 DOCUMENT_STORAGE_UNAVAILABLE`，当时本机 MinIO 未启动。请先确认已恢复。遇到同样错误记为阻塞，不要反复创建测试单，也不要把浏览器模拟下载测试当成真实文件存储已通过。**

### P02：账号

准备以下账号，使用不同浏览器或独立浏览器配置保持登录态隔离：

| 账号 | 用途 |
| --- | --- |
| 租户管理员 | 运价导入、账号和权限检查 |
| 销售 | 审核报价、修改价格、填写服务条款、发布报价 |
| 操作 | 审核订舱、退回补料、向船司／代理提交、登记和发布 SO、维护运输 |
| 客户 A | 客户主链测试 |
| 同租户客户 B | 验证不同客户公司之间的数据隔离 |
| 另一租户客户 C | 验证跨租户数据隔离 |

若要验证公司管理员与普通客户用户的区别，额外准备客户 A 的普通用户账号。使用已开通账号；本文不包含密码，不要求修改数据库。

### P03：测试资料

- [ ] 一份真实货代 Excel；日期覆盖本次测试日，至少有一条有效 FCL 运价。
- [ ] 一份小型测试 SO PDF，正文标注“测试文件”，避免误当作真实舱位凭证。
- [ ] 为测试记录统一加 `UAT-测试日期-序号` 标识，不使用真实客户在途订单做破坏性测试。

建议数据：上海 → 洛杉矶，40HQ × 1，普通货物“塑料配件”，10 箱，毛重 1,000 KG；货好日为测试日后 2 天，ETD 为测试日后 7 天，ETA 为后 25 天。按实际可用运价调整航线，不强行修改生产运价。

服务条款示例：

> 包含：本报价明细列明的海运服务与费用。不包含：目的港清关、税费与末端派送。客户申请的出口报关服务需销售另行确认费用后提供。报价在所列有效期内有效。

主链如需立即测试“实际开船／到港”，使用另一条允许回溯实际时间的测试航程，或将测试计划设置为已经发生的日期。实际发生时间不得填写未来时间；ATA 不得早于 ATD。

## 3. 主链测试：同一票业务从查价到到港

### M01：管理员导入或维护运价

1. 登录后台，进入“运价”。
2. 上传 Excel，核对 Sheet、表头行和字段映射。
3. 查看预览，修正错误后确认导入，等待完成。
4. 检查导入结果的航线、箱型、币种、售价、生效日与失效日，记录运价编号。

- [ ] 有错误时能找到具体行或字段；无效数据没有被默默当作成功。
- [ ] 有效数据导入完成，后台能检索到对应运价。
- [ ] 若用已有运价继续主链，单独记录本项导入测试仍待执行，不能顺带勾选通过。

### M02：客户查价并提交需求

1. 用客户 A 登录客户门户，进入“查运价”。
2. 按航线和箱型查到 M01 的运价，核对客户售价。
3. 点击“获取正式报价”，填写货物信息、箱量和服务需求。
4. 勾选出口报关等一项附加需求，点击“提交报价需求”，记录报价编号。

- [ ] 客户只能看到自己的可用销售价格，看不到成本、利润或内部采购说明。
- [ ] 报价需求提交后在同一“报价”入口查看，明确显示待销售处理。
- [ ] 本次运输需求中的服务是“申请服务”，不会显示为已确定提供。
- [ ] 业务进度为三段：报价确认、订舱办理、运输进展；不再出现八段流程。

### M03：销售核价、明确服务范围并发布

1. 销售打开 M02 的报价，核对客户需求和价格。
2. 必要时点击“调整价格”，填写调整原因；不要把内部成本写进客户可见条款。
3. 在“客户可见报价条款”填写上述包含／不包含服务与费用说明，保存审核信息。
4. 在“内部备注”填写一条仅员工可见的测试备注。
5. 点击“发布 Formal Quote”，确认发布。

- [ ] 保存后刷新页面，价格、条款及内部备注仍正确。
- [ ] 发布前客户不能接受未发布报价；发布后可看到正式金额与条款。
- [ ] 内部备注和改价内部原因未出现在客户页面或客户 PDF 中。

### M04：客户查看、下载并接受报价

1. 客户 A 刷新报价详情，查看“服务范围与报价条款”。
2. 下载报价 PDF，打开后核对业务编号、币种、金额、有效期及客户可见条款。
3. 点击接受报价并确认。

- [ ] 未决策时显示“待您确认”或“已查看，待您确认”，不会让客户误以为无需处理。
- [ ] 报价条款与销售保存内容一致；申请的附加服务没有被自动升级为承诺。
- [ ] PDF 能真实下载并打开。生成失败或持续等待应记录问题，不能记为通过。
- [ ] 接受后出现基于此报价订舱的入口；刷新后仍为已接受。

### M05：创建订舱并检查继承

1. 从 M04 的报价创建订舱草稿。
2. 核对航线、船司、箱型箱量、货物需求等已知信息。
3. 点击“查看报价与服务条款”，确认能返回对应报价条款；再回到订舱。
4. 补齐货好日期、包装、发货人及联系人等必填信息，保存并提交。

- [ ] 已有信息自动带入，不要求重新录入同一批需求。
- [ ] 链接指向本票来源报价，不是报价列表或其他客户报价。
- [ ] 明确提示修改订舱需求不自动改变原报价承诺。
- [ ] 必填字段缺失时有明确提示；保存后刷新不丢数据。
- [ ] 提交后为待审核，不会直接显示船司已确认舱位。
- [ ] 返回原报价再次尝试转单，不产生同一报价的重复订舱。

### M06：退回补料、重提、审核通过

1. 操作账号打开 M05 的订舱，点击“退回补充”，选择原因并填写客户可理解的说明。
2. 客户 A 查看首页待办或订舱详情，根据原因修改并重新提交。
3. 操作账号再次检查，点击“审核通过”。

- [ ] 客户收到的原因清楚，可编辑和重提；不是终态“已拒绝”。
- [ ] 客户首页待办或通知可进入正确订舱。
- [ ] 审核通过只表示资料通过，尚未表示已订舱或 SO 已取得。

### M07：向船司／代理提交

1. 操作账号从已审核通过的订舱执行提交船司／代理动作。
2. 填写页面要求的提交对象、名称、参考号及备注。
3. 保存，分别刷新后台和客户详情。

- [ ] 后台留下提交记录，进入已提交订舱、等待 SO 的阶段。
- [ ] 客户清楚当前在等待货代／承运方处理。
- [ ] 本项仅登记线下执行结果，不会要求连接真实船司接口。

### M08：内部登记 SO，暂不发布

1. 操作点击“登记 SO”，上传测试 PDF。
2. 填写 SO 编号、船名航次、ETD/ETA，以及 CY、SI、VGM 截止时间等实际字段。
3. 保存内部记录，先不要发布客户。
4. 客户 A 刷新订舱详情。

- [ ] 上传成功，后台显示 SO 内部记录和版本；订舱变为已订舱。
- [ ] 客户看不到内部 SO 编号、内部截止时间或下载按钮。
- [ ] 客户看到“暂未收到货代发布的 SO”等等待提示，不是假装文件不存在或上传失败。
- [ ] 如出现 503 或文件错误，记录为阻塞，先恢复对象存储再重试。

### M09：SO 未发布时先建运输

1. 操作在 M08 的内部 SO 已登记情况下，点击“创建 Basic Shipment”并确认。
2. 记录运输编号。
3. 客户 A 刷新订舱详情，点击“查看运输”链接。

- [ ] 不要求先把 SO 发布给客户才能创建运输。
- [ ] 客户能看到已建立的运输记录和“待开船”，内部 SO 仍不可见。
- [ ] 链接进入本票运输详情，来源订舱编号正确。
- [ ] 点击查看运输或文件不会自行改变业务状态。

### M10：发布 SO 与真实下载

1. 操作回到订舱，将已核对的 SO 发布给客户。
2. 客户 A 刷新订舱详情，或从通知进入。
3. 在页面前部查看“SO、截止时间与运输”，点击 SO 下载按钮并打开文件。

- [ ] 客户现在能看到 SO 编号、版本、船名航次及码头等已发布信息。
- [ ] CY 显示为截港，SI 显示为截单，VGM 单独显示；核对浏览器时区后的日期和时间。
- [ ] 下载文件名、正文和版本与上传文件一致；刷新后仍可下载。
- [ ] SO 发布前后的可见性确实不同；不是因为浏览器缓存或两端共用登录态造成误判。
- [ ] 运输记录仍可直接进入，不受 SO 下载动作影响。

### M11：更新运输计划、开船和到港

1. 操作打开运输详情，核对或编辑船名航次、ETD/ETA，保存后刷新。
2. 点击“标记已开船”，填写实际发生时间并确认。
3. 客户刷新运输详情与来源订舱详情，检查状态。
4. 操作点击“标记已到港”，填写不早于 ATD 的实际到港时间。
5. 客户再次检查两处状态。

- [ ] 计划信息保存成功，计划时间和实际时间可区分。
- [ ] 客户侧依次显示待开船、运输中、已到港；不直接显示枚举代码。
- [ ] 业务总进度始终归在“运输进展”，不会另跳到独立跟踪、单证或发票阶段。
- [ ] 客户详情没有后台编辑或更新状态按钮。
- [ ] 到港不显示为“已派送”“已还箱”或“费用已结清”。

## 6. 角色与数据隔离

### S01：角色按钮

- [ ] 销售只能执行其权限范围内的报价等动作，不能执行财务敏感写操作。
- [ ] 操作可处理订舱、SO 和运输，不能管理未经授权的用户或租户配置。
- [ ] 普通客户用户不会看到公司用户管理入口；公司管理员按实际权限管理本公司账号。
- [ ] 客户不能看到价格成本、内部备注、内部审核原因等员工专属内容。

### S02：同租户跨客户

1. 在客户 A 浏览器中复制一份报价、订舱、运输详情链接。
2. 在另一个独立浏览器配置中登录同租户客户 B，分别打开这些链接。

- [ ] B 无法看到 A 的业务内容；页面拒绝访问、显示不存在或返回允许的页面。
- [ ] 列表和搜索也不能检索出 A 的记录。

### S03：跨租户

将 S02 的链接用另一租户客户 C 打开。

- [ ] C 无法看到原租户任何报价、订舱或运输内容。
- [ ] 不泄露客户名称、金额、货物或文件内容。

### S04：文件权限（必要时由技术测试人协助）

使用客户 B／C 自己的认证身份，请求客户 A 文件的真实下载接口；用客户 A 身份请求尚未发布的内部 SO 下载接口。

- [ ] 两类请求均被拒绝，响应中没有文件正文。
- [ ] 操作发布后，客户 A 可下载自己的 SO，B／C 仍不可下载。

不要复制已下载的 `blob:` 地址做越权测试，那是浏览器本地文件引用。也不要把员工的登录令牌带入客户测试请求，否则无法验证客户权限。测试截图不得包含令牌或密码。仅验证按钮隐藏不足以勾选 S04；若不能执行，保留为待技术验证。
