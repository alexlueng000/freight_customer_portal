# Freight Customer Portal V1 — Rate 阶段验收清单

> 文档版本：V1.0.1
> 日期：2026-08-30
> 适用范围：Rate 后台维护、Excel 导入、客户查价、Quote 快照/状态/改价/PDF/过期
> 当前结论：Rate + Quote 功能开发完成，待业务 UAT 验收

## 1. 验收目标

确认 Rate 子阶段能够在真实数据库、真实鉴权和多租户约束下完成以下闭环：

```text
后台创建/导入 Rate
→ 客户按航线、日期、箱型和船司查价
→ 应用客户基础加价
→ 确认箱型/箱量并提交报价申请
→ 销售审核并发送 Quote
→ 修改源 Rate 后历史 Quote 价格保持不变
```

本清单覆盖 Rate + Quote 阶段；Quote → Booking 属于下一阶段验收范围，邮件通知按批准路线图在 M5 Notifications 验收。

## 2. 验收前置条件

- PostgreSQL、Redis、API、Worker 和 Web 均已启动。
- Prisma migration 已全部应用。
- 权限 seed 已执行。
- 至少准备两个不同租户，每个租户至少包含一个客户公司。
- 准备以下测试身份：
  - Tenant Admin；
  - Sales；
  - Customer Admin；
  - Customer User；
  - 另一个租户的内部或客户用户。
- 为测试客户分别配置 `NONE`、`FIXED` 或 `PERCENT` 基础加价规则。
- 验收过程不得直接修改数据库来绕过业务流程。

## 7. Rate → Quote 快照验收

### RATE-UAT-007 报价申请、箱量计价与价格快照

操作步骤：

1. 在客户查价结果中点击“申请报价”。
2. 在确认框核对航线、船司、ETD、箱型、费用明细和有效期。
3. 将箱量填写为 `2`，核对海运费和按箱附加费乘以 2，按票/按 Shipment 费用只计算一次。
4. 点击“提交报价申请”，记录报价编号、数量、单价、金额和有效期。
5. 确认客户侧状态显示“待销售确认”，且不能下载正式 PDF、接受或拒绝。
6. 使用内部 Sales/Tenant Admin 审核报价，必要时调整价格并填写原因，然后发送客户。
7. 确认发送后客户可下载 PDF、接受或拒绝报价。
8. 使用内部管理员修改源 Rate 的成本价和标准售价，再次打开原报价详情。
9. 使用相同 Rate 和箱量重新提交一份报价申请。

预期结果：

- 确认框必须要求 1–999 的整数箱量，非法或空值不能提交。
- 首份 Quote 的海运费和按箱费用按箱量计算，按票/按 Shipment 费用只计算一次。
- Quote 编号符合 `QTyyyyMM######`。
- QuoteItem 保存正确的数量、单价和金额；权威计算使用 Decimal。
- 新建 Quote 为 `DRAFT`，客户侧显示“待销售确认”。
- `DRAFT` 阶段客户不能下载正式 PDF、接受或拒绝；销售发送后进入客户决策流程。
- 原报价金额不随源 Rate 修改而变化。
- QuoteItem 保存生成时的成本价和销售价快照。
- 客户报价详情不返回或显示成本快照。
- 新提交的报价申请使用修改后的 Rate、客户加价结果和本次箱量。

结果：`□ 通过  □ 失败  □ 阻塞`

## 11. 已知边界与验收决策

V1 已批准并实现以下规则：

- 客户基础加价只应用于所选箱型的主运价。
- `isIncluded=true` 的费用不重复加入报价。
- `PER_CONTAINER` 费用只在箱型与所选箱型一致时加入，数量按 1。
- `PER_BL` 和 `PER_SHIPMENT` 费用按数量 1 加入。
- 只有与主运价同币种的费用才进入报价，不做自动汇率转换。
- 符合条件的附加费作为独立 QuoteItem 保存成本和销售快照。
- 不同币种或规则不匹配的费用不静默汇总。

业务决策：

- `□` V1 查价只展示主运价，不加入附加费用。
- `☑` V1 按上述受控规则汇总同币种附加费，并在 QuoteItem 中逐项展示。
