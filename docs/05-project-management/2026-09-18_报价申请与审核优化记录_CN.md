# 2026-09-18 报价申请与审核优化记录

状态：代码已修改并归档，等待用户统一验收；不代表最终回归通过或已上线。

## 1. 客户正式报价申请

- 「获取正式报价」由弹窗改为独立页面 `/portal/rates/[id]/quote-request`，携带箱型及原查询日期。刷新时重新按客户权限、租户、有效期读取运价；增加加载失败重试、不可用和无权限状态。
- 新增选填的「工厂预计装货日期」，以独立业务日期保存，区别于船舶 ETD。客户和后台报价详情可查看，创建审计中保留；不自动替换订舱货好日期。
- 装货日期晚于明确的开船日期时即时提醒，确认弹窗再次提醒，但允许销售继续核实；周期船期不推算日期。
- 提货地点、派送地点放在「货物概况」中，始终显示且必填。前后端拒绝缺失、空字符串和纯空白；不依赖附加服务选择，取消服务不清空地点。
- 箱量与装货日期从「当前运价条件」移入「货物概况」顶部，位于提派地点之前。
- 移除客户申请表中的贸易术语下拉框及说明，保留报价备注；历史字段及后端兼容能力保留。
- 五个模块采用编号、清晰标题和浅色分区，附加服务选中后高亮；桌面和手机采用适配布局。

## 2. 提交流程

- 校验失败后滚动到页面顺序中的第一个错误字段并聚焦，不打开确认弹窗、不发送请求。
- 校验通过后显示居中的二次确认弹窗，汇总航线、箱型箱量、开船日、装货日期、提派地点、货物和服务。
- 「返回修改」及 Escape 关闭弹窗，保留填写内容；「确认提交」才发送申请。
- 提交成功直接进入报价详情，提交按钮保持忙碌直至离开申请页面，减少重复提交机会。
- 报价详情原表格状占位改为明确的加载提示，不增加中转业务页面。

## 3. 后台报价审核

- 为客户需求、报价编辑、利润概览等区域增加浅色分区，客户可见条款与内部备注增加不同底色及可见性标签。
- 取消「调整价格」弹窗，在「报价编辑」区域内直接编辑销售单价、有效期、客户条款及内部备注，条款只维护一份。
- 价格改变时才显示必填的内部改价原因；保留既有改价时客户条款至少 3 字的要求。
- 统一「保存报价」：改价时扩展现有 prices 接口，价格、有效期、条款、备注及审计在同一事务保存；仅修改审核字段时沿用 review 接口。
- 已发布报价保持只读；未保存修改时提示先保存，仍保留独立发布及二次确认。
- 金额与利润以服务端保存结果为准，改价未保存时提示保存后重新计算，不将旧金额表现为新结果。
