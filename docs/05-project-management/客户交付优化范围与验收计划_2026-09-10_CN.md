- 提箱、装柜、报关、进港、派送、还箱等新业务节点与责任方模型。
- 完整 BL/SI/VGM 协作、提单草稿确认。
- 对账、取消费用账单、收款核销、AP/AR/总账。
- 爬虫、船司 API、实时船舶/集装箱跟踪、车队调度、海关申报。
- 新定时截止提醒任务、通知渠道或完整通知中心；本次清楚展示已有截止时间与通知。
- 品牌重设计、框架升级、与本轮无关的重构。

本轮服务承诺采用现有报价条款明确表达；结构化“申请服务/确认服务/责任方”模型另立需求。

## 4. 必须保留的业务与安全规则

1. 审核通过仅代表资料可进入订舱执行，不代表船司确认舱位。
2. SO 内部登记与发布客户独立；创建 Shipment 依赖有效内部 SO，不依赖发布。
3. 客户有没有查看文件不改变业务进度。
4. Shipment 保持 PLANNED/DEPARTED/ARRIVED/CANCELLED；到港不代表目的港派送完成或费用结清。
5. Quote、Booking、Shipment、Invoice 独立，业务详情只做关联展示。
6. 文件下载仍由服务端验证权限；客户不能获得内部 SO、内部备注、成本或其他公司的记录。
7. 现有报价条款随原报价读取；不通过前端猜测服务责任，不自动修改已接受报价。

## 5. 文档差异处理

V1.0 技术/ERD 描述完整后续链路和旧状态；V1.1 PRD 收紧交付范围。采用 V1.1 范围及已批准 ADR-001 的现行实现。V1.1 PRD 个别流程示例仍使用 REJECTED 表示补料、把发布 SO 排在创建运输前；现行 ADR 明确为 REVISION_REQUIRED，且 SO 发布不阻止运输建档。本轮记录差异并保留现行受测实现，不回退状态机。

## 6. 2026-09-11 验收与交付门槛

按真实试点账号执行；不得通过开发者改数据库完成业务。自动化使用隔离测试数据。

- [ ] 真实 Excel 导入 → 客户查价，客户不见成本。
- [ ] 客户提交报价需求 → 销售明确价格及服务条款 → 发布 → 客户查看/接受。
- [ ] 报价自动转订舱草稿，已知数据不重复填写。
- [ ] 客户提交 → 操作退回补料 → 客户重提 → 审核通过 → 提交船司/代理。
- [ ] 内部登记 SO 时客户不可见；可先创建运输；发布后客户可下载 SO 并查看截止时间。
- [ ] 开船/到港更新能在订舱关联入口和运输详情找到。
- [ ] 手机宽度可读、无流程条横向强制滚动；核心表单、空状态、失败重试可用。
- [ ] 主导航、首页、通知不导向暂缓功能；旧链接有说明，SO 下载仍可用。
- [ ] 角色权限、跨租户、同租户跨客户、隐藏文件负向检查通过。
- [ ] 生产域名/HTTPS、客户账号与品牌、对象存储下载、邮件实际投递、worker、备份恢复方案验证并记录证据。
- [ ] 不存在阻断主链、越权、错误金额或数据丢失问题；记录版本、环境、测试人、时间和遗留问题。
