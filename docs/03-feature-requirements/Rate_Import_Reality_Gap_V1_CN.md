# 运价 Excel 导入模板与真实货代运价表差异分析（V1）

> 目的：评估系统"运价导入模板"（`rate-import-template.xlsx`）与真实货代日常维护的运价表之间的差异，识别导入功能在试点环境下的可用性风险，并给出改进建议。
> 调研依据：公开的货代/外贸报价实务资料（真实海运报价单样本、船司运价表解读指南、整柜报价工具字段清单等），结合系统现有 Rate/RatePrice 数据模型。
> 日期：2026-08-31
> 结论先行：**模板骨架与真实业务的"内部运价台账"逻辑吻合（港口对/船司/箱型计价/有效期/合约号），但它是被系统规整过的理想格式。真实运价表更乱（价格挤一格、中英文混排、合并单元格）也更全（附加费可占成本 40%–60%）。直接拿货代原始 Excel 试导大概率失败，导入容错能力是试点可用性的关键短板。**

---

## 1. 系统导入模板现状

模板文件：`rate-import-template.xlsx`（工作表：`运价导入`，20 列，示例 3 行）。

| # | 列 | 示例值 | 说明 |
|---|---|---|---|

| 4-5 | 目的港代码/名称 | USLAX / Los Angeles | 同上 |

| 7 | 航线服务 | Pacific Express | Service loop |
| 8-9 | 生效/失效日期 | 2026-09-01 ~ 2026-09-30 | 有效期 |
| 10 | 预计开船时间 | 2026-09-05T08:00:00Z | ETD |
| 11 | 航程天数 | 18 | Transit time |
| 12 | 供应商名称 | Example Supplier | 采购来源 |

设计上与数据模型一一对应：`Rate`（1-15 列）+ `RatePrice`（16-19 列，按箱型展开成多行），同一 `运价编号` 聚合。**采购成本与标准售价同列并存是合理且先进的设计**——真实货代的船司/供应商费率表只有成本价，加价（markup）是货代自己心里的一笔账，模板把它结构化了。

## 2. 真实货代运价表长什么样

综合公开的报价单样本、船司费率表解读资料与整柜报价工具的字段结构，真实世界的运价/报价资料有几种形态：

### 2.1 船司/供应商发给货代的费率表（采购侧输入）

- 一张表 15–25 个行项目，一个费率对应一长串附加费代码
- 结构：表头（船司 + 有效期 + 航线）→ 港口对（常是**范围**，如 China Main Ports → North Europe）→ 箱型基础运价（20'DC/40'DC/40'HC/RF/OT/FR 各不同）→ 附加费清单 → 底部条款细则
- **附加费占总成本 40%–60%**：BAF（$100–600/柜）、THC（$100–350/柜）、PSS（旺季 $200–1000）、LSS、ISPS、EIS 等；部分按月/季浮动
- 运价类型隐含其中：FAK（普货一口价）/ Commodity（按品名，需 HS 归类）/ **NAC（指定客户合约价，带 MQC 最低货量承诺，违约有罚则）** / Spot（一票一价）
- 条款脚注：免堆期/滞箱费（Demurrage/Detention）、GRI 提前 15–30 天通知、改单/取消费用
- 有效期通常 30–90 天

### 2.2 货代内部维护的运价台账（系统模板对标的对象）

- Excel 一行一条航线，常见写法：**`USD850/1250/1400` 三个价格挤在一个单元格**（对应 20GP/40GP/40HQ），或按船司分块、合并单元格
- 港口常写中文名或俗称（"盐田""上海"），船司写俗称（"COSCO/中远""MSK/马士基"），中英文混排
- 附加费要么单独一张本地费用表（THC/DOC/订舱费/拖车费/报关费/VGM/EIR/封条费），要么全部揉进备注文字
- 有效期经常缺失或用"近期""本周"等模糊表述

### 2.3 货代发给客户的报价单（对客侧输出）

- 基础信息（收发货人、POL/POD/中转港、船司航线、柜型柜量、**贸易术语 EXW/FOB/CIF/DDU/DDP**、**报价有效期、截单/截关时间**）
- 起运港本地费用模块（THC/DOC/订舱/拖车/报关/VGM/熏蒸/内装，各口岸不同）
- 海运费 + 通用附加费（BAF/CAF/LSS/ERS/ETS/PSS/GRI）+ 航线专属申报费（美线 AMS/ISF、加线 ACI、欧线 ENS）
- 目的港费用模块（DTHC/换单/清关/关税/派送，做 DDP/DDU 才展开）
- 对应系统中的 Quote/PDF 生成，本报告不展开

## 3. 差异对照表

| 差异点 | 系统模板 | 真实运价表 | 影响 |
|---|---|---|---|
| **附加费** | 无。每箱型只有"采购成本/标准售价"一价 | 分列或塞备注，占成本 40–60% | ★★★ 价格口径不一致：模板隐含"all-in 总价"，而真实数据多为基础价+附加费，导入后总价可能严重失真 |
| **价格写法** | 一箱型一行，规整 | `850/1250/1400` 挤一格；合并单元格 | ★★★ 用户无法直接填模板，需人肉重排 |
| **港口表达** | 强制 UN/LOCODE（CNSHA）+ 英文名 | 中文名/俗称/别名混排 | ★★★ 填错代码即导入失败；需别名映射 |
| **港口范围价** | 不支持，只能点对点 | "China Main Ports → N.Europe" 范围价 + 指定港覆盖 | ★★ 范围价是合约价常见形态，需展开成多行才能导 |
| **运价类型** | 无字段 | FAK / Commodity / NAC / Spot | ★★ NAC 合约带 MQC 与罚则，Spot 仅一票有效，语义不同 |
| **币种** | 每行一个币种 | 海运费 USD、本地费 CNY 混排在一张表 | ★★ 双币种混排需拆列/拆表 |
| **有效期** | 必填且规整 | 缺失或模糊（"近期"） | ★ 需默认值策略 |
| **条款细则** | 仅状态+备注 | 免堆期/滞箱费/GRI 通知期/改单费 | ★ 影响后续费用确认，V1 可不建模 |
| **船司/供应商写法** | 标准代码 | 俗称别名（"马士基""MSK"） | ★ 需别名映射 |

## 4. 风险评估

1. **导入失败的表象是格式问题，本质是"要求用户按系统的方式思考"**。货代文员面对模板的第一反应是"这比我现在的表还难填"，然后退回手工录单或干脆不维护——价格数据一旦不新鲜，客户查到错价，门户价值归零（参见《真实业务对照评估》场景 2 的内部侧脆弱环节）。
2. **总价失真是隐性风险**：若用户把基础运价填进"采购成本"而附加费留在备注里，系统算出的 Quote 将系统性偏低，月底对账爆发冲突——这比导入报错更危险。
3. **试点验收口径**：如果试点选用的 3 家货代维护价格的方式恰好规整，测试会"假性通过"；真实环境差异极大，**必须用货代的历史原始表做回放测试**。

## 5. 改进建议（按优先级）

### P0 —— 试点前建议完成（低成本容错）

1. **单元格多价拆分**：识别 `850/1250/1400` / `850, 1250, 1400` / `850 1250 1400` 写法，按 20GP/40GP/40HQ 顺序自动拆成三行（拆分前预览确认）
2. **港口别名映射**：内置常用中国港口 UN/LOCODE 别名表（盐田→CNYTN、上海/沪→CNSHA、宁波→CNNGB……），支持中文名模糊匹配并回显确认
3. **船司别名映射**：COSCO/中远、MSK/马士基/MAEU、MSC/地中海……同上
4. **错误报告可下载**：逐行报错（行号 + 列 + 原因 + 建议值），并提供"修正后重传"只重导失败行的能力（导入作业已有异步框架，补前端闭环）

### P1 —— 试点期迭代（价格口径正确性）

5. **价格口径显式化**：导入时让用户勾选"该价格是否 all-in 含附加费"；非 all-in 时提示附加费未计入（或提供附加费列，见 6）
6. **附加费列支持**：允许模板追加常见附加费列（THC/DOC/AMS/ISF/ENS/LSS），导入时落成 Surcharge 明细（对应 Quote 的附加费汇总规则）；此改动同时缓解《真实业务对照评估》差距 #1 的报价口径问题
7. **双币种支持**：海运费 USD 与本地费 CNY 分列，导入时按币种分别落账

### P2 —— V1.5/V2 Backlog（合约价形态）

8. **范围价展开**：`China Main Ports` 类范围价一次展开为多港口对 Rate（需维护港口分组）
9. **运价类型字段**：FAK / Commodity / NAC / Spot；NAC 关联客户与 MQC，Spot 限定单票 Booking 有效
10. **免费试算**：导入预览页显示"按此表生成的报价样例"，让维护者导完立刻自查口径

### 验收标准建议

- 拿 ≥2 家真实货代近 3 个月的原始运价表做回放：不做任何人工重排的前提下，P0 容错能消化 ≥80% 的行；剩余行在错误报告中可读、可修
- 附加费口径抽检：随机 10 条导入价与货代实际报价核对，偏差 >5% 即口径有问题
